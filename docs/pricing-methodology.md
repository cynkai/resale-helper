# 가격 비교·계산 규칙

구현 위치: `src/lib/domain/` (`compare.ts`, `net.ts`, `money.ts`, `price-input.ts`, `csv.ts`, `triage.ts`). 규칙은 `tests/unit/`에서 테스트한다.

## 1. 가격 유형은 섞지 않는다

- 모든 가격 자료는 `ASKING` / `SOLD_LISTING` / `VERIFIED_SALE` / `BUYBACK_QUOTE` / `USER_REPORTED` 중 하나를 반드시 가진다.
- 비교·요약은 **유형별로 따로** 한다. 유형을 넘나드는 평균·중앙값은 계산하지 않는다.
- 판매 중 자료의 요약은 "판매 중 희망가 중앙값"이라고 부른다. "실거래 평균" 같은 이름은 쓰지 않는다.
- 유형과 별도로 입력 경로(직접 입력/CSV/앱 내 공식 API/확장으로 직접 담기/외부 도구 가져오기), 데모 여부, 출처 이름·URL을 저장한다.

### 유형 승격 금지

- 직접 입력, CSV, 브라우저 확장(`CLIP`), 가져오기 API(`EXTERNAL`)는 `VERIFIED_SALE`로 저장할 수 없다. 입력 폼에는 선택지가 없고, 서버 검증에서도 거부한다. CSV는 해당 행을 오류로 건너뛴다(조용히 다른 유형으로 바꾸지 않는다).
- URL, "확인 방법" 메모, 판매완료 표시는 유형을 바꾸지 못한다.
- API 경로도 그 제공자가 실제 체결가를 제공한다고 문서로 확인되고(`attestsVerifiedSales`) 검증 근거가 함께 있을 때만 허용한다. 현재 그런 제공자는 없다.

## 2. 비교에 포함·제외하는 기준

자료마다 아래를 차례로 확인하고, 하나라도 걸리면 **제외하되 사유와 함께 화면에 남긴다.**

| 제외 사유 | 조건 |
|---|---|
| 직접 제외함 | 사용자가 "빼기"를 누른 자료 |
| 외화 자료 | 통화가 KRW가 아님 |
| 다른 상품 | 자료의 식별정보(ISBN·모델명)가 내 물건과 다름 |
| 묶음 상품 | 단품/묶음이 "묶음" |
| 상태가 다름 | 자료의 상태 등급이 내 물건과 다름 |
| 견적 유효기간 만료 | 매입 견적의 유효기간이 오늘보다 이전 |
| 기준 기간보다 오래됨 | 확인일이 선택한 기간(기본 180일) 밖 |

- 식별정보는 ISBN이면 ISBN-13으로, 그 외에는 공백·하이픈·대소문자를 무시하고 비교한다. ISBN-10으로 적힌 자료도 같은 책으로 맞춘다.
- 식별정보나 상태가 **비어 있는** 자료는 제외하지 않고 "미확인" 경고를 붙인다. 사용자가 그 물건의 자료라고 직접 연결한 것이기 때문이다.
- 상태는 "같은 등급인가"만 본다. **등급 차이를 금액으로 보정하지 않는다**("상태가 한 단계 낮으면 20% 할인" 같은 근거 없는 규칙을 두지 않는다).
- 판본은 자동으로 비교하지 않는다. ISBN이 같으면 보통 판본도 같지만, 사용자가 등록 화면에서 제목과 판본을 직접 확인하게 한다.
- 기준 기간은 30일 / 90일 / 180일 / 1년 / 전체 중에서 고른다. 각 자료에 "며칠 전 확인"을 항상 표시한다.
- 기간 안에 있더라도 **90일보다 오래 전에 확인한 자료**에는 "확인한 지 오래됨" 경고를 붙인다. 비교에서 빼지는 않는다. 90일도 표시 정책일 뿐 근거 있는 유효기간이 아니다.

## 3. 요약 가격과 표본 수

- 유형별로 적합한 자료가 **3건 이상**이면 중앙값·최솟값·최댓값·건수를 보여 준다.
- **3건 미만이면 요약 가격을 내지 않고** 개별 자료만 보여 준다. 자료가 없으면 없다고 표시한다.
- **3건은 MVP의 화면 표시 정책이다.** 3건이면 통계적으로 정확하다는 뜻이 아니다. 한두 건으로 "시세"를 말하는 일을 막기 위한 최소선일 뿐이다.
- 평균이 아니라 중앙값을 쓴다(극단값 하나에 덜 흔들린다). 신뢰도 백분율 같은 수치는 만들지 않는다.

## 4. 중복

- **같은 매물**로 보는 경우: (출처 이름 + 출처의 매물 번호)가 같거나, 정규화한 원문 URL이 같을 때.
- URL 정규화: `www.`·`m.` 접두어, 끝 슬래시, 해시, 추적 파라미터(`utm_*`, `fbclid`, `gclid` 등)를 무시하고 나머지 파라미터는 정렬한다.
- **금액·날짜가 같다는 이유로는 중복으로 보지 않는다.** 같은 가격의 서로 다른 매물은 각각 표본이다.
- 중복이면 저장을 거부한다. 같은 매물의 가격이 바뀌었으면 기존 자료를 수정한다(매물당 한 건).
- 한계: 매물 번호도 URL도 없이 입력한 자료끼리는 중복을 가려낼 수 없다.

## 5. 견적과 오래된 자료

- 매입 견적에는 유효기간과 감액 조건을 적을 수 있다. 원문 URL이 없으면 어떻게 받은 견적인지 메모가 필수다.
- 유효기간이 지난 견적은 "만료"로 표시하고 비교에서 제외한다.
- 만료된 견적은 실수령액 계산의 기준 금액으로 고를 수 없다. 저장한 뒤에 만료되면 계산 결과에 경고가 붙는다.
- 유효기간을 적지 않은 견적은 만료 처리하지 않는다(알 수 없는 것을 만료로 단정하지 않는다). 대신 확인일이 기준 기간을 벗어나면 제외된다.

## 6. 실수령액

```
실수령액 = 선택한 판매금액 − 판매자 부담 수수료 − 판매자 부담 배송비 − 포장비 − 교통비
```

- **모름(빈칸)과 0원을 구분한다.** DB에는 모름을 `NULL`, 0원을 `0`으로 저장한다.
- 비용이 하나라도 모름이면 실수령액을 내지 않고 "계산 불완전"으로 표시한다. 참고로 "입력한 비용만 뺀 금액"을 보여 주되, 실제로는 그보다 적을 수 있다고 함께 적는다.
- 두 방법의 차액은 양쪽이 모두 완전할 때만 계산한다.
- **손익분기 개인 판매금액**: 개인 판매의 실수령액이 업체 실수령액과 같거나 많아지는 가장 낮은 개인 판매금액을 보여 준다(수수료율의 반올림까지 반영). 업체 실수령액이 완전하고 기준 자료에 문제가 없으며, 개인 판매 비용을 모두 알 때만 계산한다. 입력한 비용으로 한 산수이며 그 금액에 팔린다는 예측이 아니고, 시간은 반영하지 않는다.
- 수수료는 금액 또는 비율로 사용자가 입력한다. **플랫폼 수수료율을 코드에 넣지 않는다.**
- 기준 금액의 성격을 구분해 표시한다: 직접 입력한 예상 금액 / 가격 자료를 참고한 예상 금액 / 매입 견적 기준. 실제 판매 결과는 별도 테이블에 "내가 기록한 결과"로 저장한다.
- 가격 자료를 기준으로 고르면 화면에서 보낸 금액이 아니라 **서버가 그 자료의 금액을 읽어** 사용한다.
- 판매 방법을 선택하면 그 시점의 판매금액과 실수령액을 함께 저장해, 나중에 실제 결과와 비교한다. 선택 당시 계산이 불완전했으면 실수령액은 비워 둔다.
- 선택한 뒤 그 방법의 금액이나 비용을 바꾸면 "선택 당시 값과 다르다"고 알린다. 다시 선택해야 저장된 숫자가 바뀐다.

### 기준 자료가 바뀐 계산

가격 자료를 기준으로 고른 계산은 그 자료의 금액을 복사해 저장한다. 나중에 자료가 바뀌면 저장된 금액은 근거를 잃는다. 화면을 열 때마다 다시 확인하고, 아래 중 하나라도 해당하면 경고를 띄운다.

| 경우 | 판단 |
|---|---|
| 기준 자료가 삭제됨 | 저장 당시 유형 기록은 남아 있는데 자료 id가 비어 있음 |
| 기준 자료의 금액이 바뀜 | 자료 금액 ≠ 저장된 금액 |
| 기준 자료가 외화로 바뀜 | 통화가 KRW가 아님 |
| 기준 견적이 만료됨 | 유효기간이 오늘보다 이전 |

경고가 있는 계산은 두 방법의 차액 비교에 쓰지 않고, 그 방법은 **기준 금액을 다시 저장하기 전까지 선택할 수 없다**(화면과 서버 모두에서 막는다).
- 예상 소요시간은 사용자가 적는 값이다. 앱이 판매 기간을 추정하지 않는다.

## 7. 금액과 반올림

- 금액은 **최소통화단위 정수**로 저장·계산한다(KRW·JPY는 1 단위, USD·EUR은 센트). 부동소수점으로 금액을 계산하지 않는다.
- 입력은 문자열로 받아 정수로 바꾼다. 음수, 지수 표기, 통화가 허용하지 않는 소수 자릿수는 거부한다.
- 반올림이 일어나는 곳은 세 군데뿐이다. 모두 **0.5 이상 올림(half-up)** 이고 정수 연산(BigInt)으로 처리한다.
  1. 비율 수수료: `판매금액 × 요율`의 원 미만. 요율은 소수 둘째 자리까지(만분율 정수로 저장).
  2. 짝수 건의 중앙값: 가운데 두 값 평균의 원 미만.
  3. 배분의 시간당 추가 수익: `차액 × 60 ÷ 추가 시간(분)`의 원 미만(10절).
- 덧셈·뺄셈에서는 반올림이 생기지 않는다.

## 8. 통화

- 비교와 실수령액 계산은 KRW만 대상으로 한다.
- 외화 자료(USD·JPY·EUR)는 등록할 수 있지만 **원래 통화로만 표시**하고 비교에서 제외한다. 환율을 입력받지 않으므로 원화로 환산하지 않고, 서로 다른 통화를 더하지 않는다.

## 9. 데모 격리

- 데모 자료는 `is_demo = true`로 저장하고, 목록·상세·비교·내보내기 조회는 모두 현재 모드로 범위를 제한한다.
- 데모 물건에 추가한 가격 자료는 자동으로 데모 자료가 된다. 데모 초기화·삭제는 데모 자료만 지운다.

## 10. 배분 판단

물건 배분 화면(`/triage`)은 보유 중·판매 중 물건마다 "직접 팔 가치가 있는가"를 판단한다. 물건 상세에서 저장한 업체·직접 판매 계산(6절)을 그대로 쓰고 새 계산을 만들지 않는다.

```
차액 = 직접 판매 실수령액 − 업체 실수령액           (netDifference)
추가 시간 = 직접 판매 예상 소요시간 − 업체 판매 예상 소요시간  (분)
시간당 추가 수익 = 차액 × 60 ÷ 추가 시간                   (원 미만 half-up)
```

판단은 위에서부터 차례로 확인한다.

| 순서 | 조건 | 판단 | 이유 코드 |
|---|---|---|---|
| 1 | 업체 또는 직접 판매 계산이 없음 | 판단 보류 | `NO_BUYBACK` / `NO_DIRECT` |
| 1 | 어느 쪽이든 비용에 모름이 있음 | 판단 보류 | `INCOMPLETE_COST` (빠진 항목 포함) |
| 1 | 어느 쪽이든 기준 자료가 삭제·변경·만료·비원화 | 판단 보류 | `BASIS_ISSUE` (해당 이슈 포함) |
| 2 | 차액 ≤ 0 | 업체 | `DIRECT_NOT_HIGHER` |
| 3 | 업체 또는 직접 판매 소요시간 모름 | 판단 보류(차액은 표시) | `NO_MINUTES` (모르는 쪽 포함) |
| 4 | 추가 시간 ≤ 0, 차액 > 0 | 직접 판매(0으로 나누지 않음) | `NO_EXTRA_TIME` |
| 5 | 시간당 가치 모름 | 판단 보류(시간당 추가 수익은 표시) | `NO_TIME_VALUE` |
| 6 | 시간당 추가 수익 ≥ 시간당 가치 | 직접 판매 | `PER_HOUR_AT_LEAST_TIME_VALUE` |
| 6 | 시간당 추가 수익 < 시간당 가치 | 업체 | `PER_HOUR_BELOW_TIME_VALUE` |

- 1번 조건들은 한꺼번에 모아 보여 준다. 하나를 고친 뒤에야 다음 빠진 것을 알게 되는 일을 줄이기 위해서다. 소요시간과 시간당 가치를 둘 다 모를 때도 두 사유를 함께 보여 준다.
- 비교는 화면에 표시되는 반올림된 시간당 추가 수익으로 한다. 표시된 숫자와 판단이 어긋나지 않게 하기 위해서다. 경계(같음)는 직접 판매로 본다.
- **시간당 가치와 소요시간은 사용자가 어림한 값이며 앱이 예측하지 않는다.** 시간당 가치·수수료율·소요시간에 기본값을 두지 않는다. 비워 두면 모름(null)이고, 0은 유효한 값이다(시간당 가치 0원 = 시간을 공짜로 봄).
- 업체에 넘기는 데도 시간이 들기 때문에, 나누는 시간은 직접 판매에 **추가로** 드는 시간(직접 − 업체)이다. 어느 쪽이든 소요시간을 비워 두면 0분으로 치지 않고 보류한다. 시간이 안 들면 0을 입력한다.
- 판단은 확신도나 점수로 표현하지 않는다.

판단을 바꾸지 않고 붙이는 경고:

- 직접 판매 기준 자료가 판매 중 희망가(`ASKING`) — 실제로는 더 적게 받을 수 있다.
- 기준 자료 없이 직접 입력한 예상 금액 — 직접 어림한 금액 기준(업체·직접 판매 각각).
- 이미 고른 판매 방법(`items.chosen_method`)과 판단이 다름. 판단 보류일 때는 붙이지 않는다.

요약은 판단별 건수만 보여 준다. 출처와 기준이 다른 금액을 더한 합계는 만들지 않는다.
