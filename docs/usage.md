# 사용 안내

README에서 옮긴 상세 안내입니다. 개요는 [README](../README.md)를 보세요.

## 화면
| 경로 | 화면 |
|---|---|
| `/` | 내 물건 목록. 물건마다 다음에 할 일, 할 일별로 걸러 보기, 정렬, 답하지 않은 제안 표시 |
| `/items/new`, `/items/[id]` | 물건 등록, 물건 상세(가격 비교 → 실수령액 → 판매 방법 → 판매글·올린 가격 → 받은 제안 → 판매 결과 → 기록 한눈에 보기) |
| `/items/import` | 물건 CSV로 한꺼번에 등록·내보내기 |
| `/triage` | 물건 배분: 아직 팔지 않은 물건마다 직접 판매·업체·판단 보류. 판단별 건수만 요약 |
| `/checkup` | 자료 점검(만료된 견적·오래된 자료·다시 확인할 계산·답하지 않은 제안) |
| `/results` | 판매 결과 돌아보기 |
| `/presets`, `/templates` | 내 비용 묶음, 내가 만드는 판매글 템플릿 |
| `/trash` | 휴지통(삭제한 물건 되살리기·완전히 지우기) |
| `/settings` | 설정: 가져오기 토큰, 허용할 브라우저 확장, 백업 사본 |

## 가격 유형
모든 가격 자료는 아래 유형 중 하나로 저장되고, **유형이 다른 가격은 하나의 숫자로 합치지 않습니다.**

| 유형 | 화면 표시 | 의미 |
|---|---|---|
| `ASKING` | 판매 중 희망가 | 지금 판매글에 올라와 있는 희망 가격. 그 가격에 팔렸다는 뜻이 아님 |
| `SOLD_LISTING` | 판매완료 게시가 | 판매완료로 표시된 게시글의 가격. 최종 합의금액은 다를 수 있음 |
| `VERIFIED_SALE` | 검증된 체결가 | 실제 체결가격을 제공한다고 확인된 출처의 거래가격. **직접 입력·CSV로는 저장할 수 없음** (현재 이 유형을 만들 수 있는 연동 없음) |
| `BUYBACK_QUOTE` | 매입 견적 | 매입업체가 제시한 견적. 유효기간·검수 감액 조건이 있을 수 있음 |
| `USER_REPORTED` | 직접 입력한 거래가 | 내가 직접 입력한 거래가격. 외부에서 검증되지 않음 |

## 준비물

- Node.js **22.13 이상** (개발·검증은 Node 26.0.0에서 진행)
- pnpm **11** (`packageManager: pnpm@11.5.2`)
- macOS / Linux. `better-sqlite3` 네이티브 모듈이 설치 중 빌드되거나 미리 빌드된 바이너리를 내려받습니다.

## 설치와 실행

```bash
pnpm install
```

```bash
cp .env.example .env.local
```

```bash
pnpm db:migrate
```

```bash
pnpm dev
```

브라우저에서 <http://127.0.0.1:3000> 을 엽니다. (`.env.local`은 선택 사항입니다. 없어도 동작합니다.)

- `pnpm db:migrate` — `data/resale.db`를 만들고 스키마를 적용합니다. 앱 시작 때도 자동 적용되므로 건너뛰어도 됩니다.
- `pnpm db:seed:demo` — 데모(가상) 자료를 다시 만듭니다. 실제 자료는 건드리지 않습니다.
- `pnpm db:generate` — `src/lib/db/schema.ts`를 바꾼 뒤 마이그레이션 SQL을 생성합니다.
- `pnpm db:restore <파일>` — 백업 파일로 복구합니다(아래 "백업과 복구").

| 물건 배분, 자료 점검, 판매 결과 돌아보기 | ✅ | |
| 가격 변동 이력, 전체 내보내기(JSON), DB 백업·복구 | ✅ | |
| 판매글 초안(템플릿), 판매 결과 기록 | ✅ | LLM을 쓰지 않음 |
| ISBN 형식·체크섬 검증 | ✅ | 로컬 계산 |
| 서지정보 자동 채움 — Open Library | ✅ | 키 불필요. 한국어 도서는 없는 경우가 많음 |
| 서지정보 자동 채움 — 국립중앙도서관 | 🔑 `NLK_CERT_KEY` | 회원가입·신청·담당자 승인 필요. **키가 없어 실제 호출은 검증하지 못함** |

## 실제 사용 모드와 데모 모드

- **실제 사용 모드(기본)**: 앱을 켜면 항상 이 모드입니다. 내가 입력한 자료만 보입니다.
- **데모 모드**: 화면 맨 아래 "가상 데이터로 둘러보기(데모 보기)"를 눌러야 들어갑니다. 모든 화면 위에 "데모 모드" 띠가 뜨고 물건·가격에 "가상 데이터" 표시가 붙습니다. 값은 전부 지어낸 것이며 실제 시세와 무관합니다.
- 데모 자료는 DB에서 `is_demo`로 구분되고, 목록·비교·요약·CSV 내보내기는 항상 현재 모드의 자료만 사용합니다. 데모 모드에서 실제 물건 주소로 들어갈 수 없고, 그 반대도 마찬가지입니다.

## 실수령액 산식

```
실수령액 = 선택한 판매금액 − 판매자 부담 수수료 − 판매자 부담 배송비 − 포장비 − 교통비
```

- **"모름"과 "0원"은 다릅니다.** 비용 칸을 비워 두면 "모름"이고, 하나라도 모르면 실수령액 대신 **"계산 불완전"** 으로 표시합니다. 비용이 없으면 0을 입력하세요.
- 수수료는 금액(원) 또는 비율(%)로 직접 입력합니다. **앱에 내장된 플랫폼 수수료율은 없습니다.** 이용할 판매처의 최신 공식 안내를 확인해 넣으세요.
- 비율 수수료는 원 미만을 반올림(0.5 이상 올림)합니다.
- 기준 금액이 "직접 입력한 예상 금액"인지 "매입 견적"인지 결과 상자에 표시합니다. 예상 금액으로 계산한 실수령액은 예상일 뿐입니다.
- 유효기간이 지난 견적은 기준 금액으로 고를 수 없습니다. 저장한 뒤 기준 자료가 만료·수정·삭제되면 경고가 붙고, 다시 저장하기 전까지 그 방법은 선택할 수 없습니다.
- 예상 소요시간은 내가 어림해 적는 값입니다. 앱이 판매 기간을 예측하지 않습니다.
- 두 방법의 차액은 양쪽 비용이 모두 입력됐을 때만 계산합니다.
- **판매처별 계산**: 같은 방식 안에 판매처 이름을 달리해 계산을 여러 개 둘 수 있습니다(예: 택배 거래와 직거래). 이름은 직접 적는 구분용이며, 앱에 내장된 판매처 목록이나 요율은 없습니다. 계산이 여러 개인 방식은 **"기준으로 쓰기"로 하나를 정해야** 두 방법의 차액·손익분기·배분을 계산합니다. 앱이 가장 유리한 계산을 대신 고르지 않습니다. 저장한 계산은 입력한 순서대로 나란히 보여 줍니다(순위 아님). 배분 화면에서는 기준이 아닌 계산도 "판매처별로 따져 보기"로 같은 규칙에 넣어 볼 수 있습니다.
- **손익분기 개인 판매금액**: 개인 판매금액이 얼마 이상이어야 업체 판매와 실수령액이 같아지는지 보여 줍니다(흥정할 때의 하한선). 그 금액에 팔린다는 예측이 아니고, 들이는 시간은 반영하지 않습니다.

자세한 규칙: [docs/pricing-methodology.md](pricing-methodology.md)

## 물건 배분 판단 (`/triage`)

```
차액(extra)        = 직접 판매 실수령액 − 업체 실수령액
추가 시간          = 직접 판매 예상 소요시간 − 업체 판매 예상 소요시간
시간당 추가 수익   = 차액 ÷ (추가 시간(분) ÷ 60)   ※ 원 미만 반올림(0.5 이상 올림)
```

- 차액이 0 이하면 시간과 무관하게 **업체**, 더 받는데 추가 시간이 0 이하면 **직접 판매**, 시간당 추가 수익이 내 시간당 가치 **이상이면 직접 판매**, 미만이면 업체입니다.
- 비용·소요시간·시간당 가치 중 하나라도 모르면(빈칸) **판단 보류**와 함께 무엇을 채우면 되는지 보여 줍니다. 빈칸을 0으로 메우지 않습니다. 시간당 가치 0원은 "시간을 공짜로 본다"는 유효한 값입니다.
- 시간당 가치, 수수료율, 소요시간에 **앱이 정한 기본값은 없습니다.** 모두 내가 어림해 입력합니다.
- 판매 중 희망가를 기준으로 한 계산, 기준 자료 없이 어림한 금액, 이미 고른 방법과 다른 판단에는 경고를 붙입니다(판단은 바꾸지 않음).
- 여러 물건의 금액은 더하지 않고 판단별 건수만 보여 줍니다.
- 물건마다 **기준선**을 함께 보여 줍니다: 직접 판매금액이 얼마 이상이면 업체와 실수령액이 같아지는지, 얼마 이상이면 판단이 직접 판매로 바뀌는지. 입력한 비용으로 한 산수이며 예측이 아닙니다.

## 실제 연동 / 수동 기능 / 미구현

**실제 연동(외부 호출)**

- 서지정보: Open Library Books API (키 불필요, 실제 호출 확인함)
- 서지정보: 국립중앙도서관 ISBN 서지정보 API (문서 기준 구현, 키가 없어 실제 호출 미검증)

**수동 기능**

- 가격 자료는 사람이 확인해 넣습니다: **직접 입력**, **CSV**, 또는 보고 있던 매물 한 건을 버튼으로 저장하는 **브라우저 확장 "직접 담기"**.
- 가져오기 API(`POST /api/import/prices`): 내가 만든 로컬 도구가 가격 자료를 넣는 문. 기본은 꺼져 있고 토큰을 만들어야 켜집니다. 자료를 어디서 얻는지는 그 도구의 책임입니다.
- 수수료율·배송비·포장비·교통비·예상 소요시간, 판매글 다듬기, 판매처 등록, 판매 결과 기록.
- 물건 배분(`/triage`): 시간당 가치를 한 번 입력해 두면 물건마다 직접 판매·업체·판단 보류를 나눕니다. 시간당 가치는 데모·실제 모드별로 따로 저장됩니다.
- 물건 한꺼번에 등록(`/items/import`): 물건 목록 CSV를 올리면 물건 등록 폼과 같은 검증을 거쳐 한 번에 등록합니다. 필수 열은 `category`, `name`, `condition`이고 시세·판매 가격 열은 받지 않습니다(내가 산 가격 `purchase_amount`·`purchase_date`만 선택으로 받음). 카테고리·이름·식별자가 같은 물건이 이미 있으면 그 행은 건너뛰므로 같은 파일을 다시 올려도 두 번 등록되지 않습니다. 같은 형식으로 내려받을 수도 있습니다(`/api/export/items`).
- 내 비용 묶음(`/presets`): 자주 쓰는 비용 조합(수수료, 배송비, 포장비, 교통비, 소요시간)을 직접 저장해 두고 계산을 만들 때 불러옵니다. 값은 모두 내가 적은 것이고 빈칸은 모름으로 옵니다. 불러온 뒤 물건마다 고칠 수 있습니다.
- 판매글 템플릿(`/templates`): 내가 자주 쓰는 판매글 틀을 직접 써 두고 `{이름}`·`{상태}`·`{가격}` 같은 자리표시를 넣으면, 물건 화면에서 그 물건의 정보로 채워 줍니다. 입력하지 않은 값이 든 줄은 통째로 빼고 알려 줍니다(지어내지 않음). 판매처별 양식이나 글자 수 제한은 앱에 없습니다.
- 산 가격: 물건 정보에 내가 산 가격과 산 날짜를 적어 두면(선택), 계산의 예상 실수령액과 실제 판매 결과를 산 가격과 견줘 보여 줍니다. 모르면 비워 두고 거저 얻었으면 0을 넣습니다. 판매글 초안과 템플릿에는 들어가지 않습니다.
- 백업 사본: 설정 화면에서 "지금 백업 사본 만들기"를 누르면 DB 전체(휴지통 포함) 사본을 `data/backups/<DB 이름>/`에 만듭니다. 버튼을 누를 때만 만들고 자동으로 지우지 않습니다. 되돌릴 때는 앱을 끄고 `pnpm db:restore <사본 경로>`를 씁니다.
- 휴지통(`/trash`): 물건이나 가격 자료를 삭제하면 바로 지워지지 않고 휴지통으로 갑니다. 휴지통의 물건·가격 자료는 어느 화면·비교·내보내기에도 쓰이지 않으며, 물건을 되살리면 가격 자료·계산·기록이, 가격 자료를 되살리면 이전 값 기록이 그대로 돌아옵니다. 휴지통에 있는 매물과 같은 매물(출처 ID·원문 URL이 같음)은 다시 넣을 수 없습니다. 자동으로 비워지지 않고, "완전히 지우기"와 "휴지통 비우기"는 되돌릴 수 없습니다. DB 백업 파일에는 휴지통의 자료도 들어 있습니다.
- 같은 물건 하나 더 등록: 물건 화면의 버튼으로 물건 정보만 베껴 새 물건을 만듭니다. 가격 자료와 계산은 물건마다 따로 넣습니다.
- 기록 한눈에 보기: 물건 화면 맨 아래에 그 물건의 가격 자료 확인, 올린 가격, 받은 제안, 방법 선택, 판매 기록을 날짜순으로 보여 줍니다.
- 올린 가격 기록: 내 판매글에 올린 가격과 바꾼 날짜를 물건 화면에 적어 두면, 가격을 어떻게 바꿔 왔는지와 지금 가격이 손익분기 이상인지 보여 줍니다. 얼마에 올리라고 하거나 언제 팔릴지 예측하지 않고, 가격 자료·비교에는 넣지 않습니다.
- 받은 제안: 구매 희망자가 부른 금액을 물건 화면에 적어 두면, 그 금액을 내 개인 판매 계산의 비용에 넣어 예상 실수령액과 업체 판매 대비 차이를 보여 줍니다. 가격 자료가 아니라서 비교·요약에는 들어가지 않고, 받을지 말지는 앱이 정하지 않습니다. 상대방 닉네임·연락처를 적는 칸은 없습니다.
- 판매 결과 돌아보기(`/results`): 판매 방법을 고를 때의 예상과 실제 기록을 물건별로 비교. 건수만 세고 금액 총액은 만들지 않습니다. 카테고리·고른 방법·판매처별로 묶어 볼 수 있습니다(역시 건수만). 고를 때 적어 둔 판매처와 실제로 판 곳이 같았는지도 건수로 보여 줍니다. 실제 비용을 항목별(수수료·배송비·포장비·교통비)로 적으면 어느 항목을 잘못 어림했는지 물건 화면에서 보고, 돌아보기에서는 항목별 건수로 봅니다.
- 배분·판매 결과 CSV: 두 화면의 물건별 값을 CSV로 내려받습니다(`/api/export/triage`, `/api/export/results`). 합계·평균 행은 없고 모르는 값은 빈 칸입니다.
- 자료 점검(`/checkup`): 만료된 견적, 유효기간이 남은 견적, 확인한 지 90일 넘은 자료, 기준 자료가 바뀐 계산, 답하지 않은 제안을 물건별로 모아 봅니다. 출처에서 다시 확인했는데 가격이 그대로면 "오늘 다시 확인함"으로 확인일만 갱신합니다.
- 가격 변동 이력: 가격 자료를 고치면 이전 값이 그 자료 아래에 남습니다. 비교와 요약에는 지금 값만 씁니다.
- 구성이 같은 자료끼리 비교: 가격 자료에 "구성이 내 물건과 다름"이라고 표시하면 비교에서 빠집니다. 앱이 구성품 글자를 비교해 추측하지 않습니다.
- 전체 DB 백업 다운로드와 `pnpm db:restore` 복구, 읽을 수 있는 전체 내보내기(JSON).

**미구현**

- 가격 자동 조회·자동 수집(어떤 출처도 연동되어 있지 않고, 수집기를 제공하지 않음), `VERIFIED_SALE` 자료 생성
- 게임기·전자기기 자동 식별, 구성품에 따른 가격 보정
- 환율 자동 조회, 외화 자료를 원화 비교에 넣기(외화 자료는 비교에서 제외. 직접 입력한 환율이 있으면 환산 참고값만 보여 줌)
- 사진 업로드, 바코드 카메라 인식, 계정, 판매처 자동 게시, 공개 배포

출처별 검토 결과: [docs/data-sources.md](data-sources.md)

## 가져오기 API

로컬 프로그램이 가격 자료를 넣을 수 있는 인증된 엔드포인트입니다. 자세한 규칙은 [docs/integrations.md](integrations.md).

1. 앱 화면 맨 아래 **설정** → "토큰 만들기". 토큰은 그때 한 번만 보이니 바로 복사합니다.
2. 토큰을 환경변수에 넣고 호출합니다.

```bash
export RESALE_IMPORT_TOKEN='<복사한 토큰>'
```

```bash
curl -sS http://127.0.0.1:3000/api/import/prices -H "Authorization: Bearer $RESALE_IMPORT_TOKEN" -H "Content-Type: application/json" -d '{"itemId": 1, "records": [{"price_type": "ASKING", "amount": 15000, "source_name": "예시마켓", "external_id": "101", "checked_date": "2026-11-01"}]}'
```

- 레코드 필드는 아래 "CSV 형식"의 열과 같습니다. 그 밖의 필드(판매자 정보 등)가 있으면 그 행은 거부됩니다.
- `VERIFIED_SALE`은 만들 수 없고, 중복 매물은 거부되며, 항상 실제 사용 모드의 물건에만 저장됩니다.
- 한 번에 100건, 본문 256KB까지.

보안·접근 통제와 사용 기록은 [integrations.md](integrations.md#접근-통제), 브라우저 확장은 [integrations.md](integrations.md#브라우저-확장-직접-담기)에 있습니다.

## CSV 형식

물건 상세 화면의 "CSV로 한꺼번에 가져오기"에서 사용합니다. 예시 파일: [examples/prices-example.csv](../examples/prices-example.csv)

```csv
price_type,amount,currency,source_name,source_url,external_id,checked_date,condition,bundle_type,shipping_included,quote_valid_until,deduction_terms,memo
ASKING,15000,KRW,예시마켓,https://example.com/items/101,101,2026-11-01,GOOD,SINGLE,NO,,,
SOLD_LISTING,13000,KRW,예시마켓,https://example.com/items/77,77,2026-10-20,GOOD,SINGLE,UNKNOWN,,,판매완료 표시 확인
BUYBACK_QUOTE,6000,KRW,예시서점,,,2026-11-05,GOOD,SINGLE,UNKNOWN,2026-11-12,필기 발견 시 감액,매장 방문 견적
```

- 필수 열: `price_type`, `amount`, `source_name`, `checked_date`
- 선택 열: `currency`(기본 KRW), `fx_rate`·`fx_date`(외화 자료의 환산 참고용 환율과 기준일. 함께 넣어야 하며 원화 자료에는 넣을 수 없음), `source_url`, `external_id`, `trade_date`, `product_identifier`, `condition`, `components`, `components_match`(구성이 내 물건과 같은지: YES/NO/UNKNOWN, NO면 비교에서 제외), `bundle_type`(SINGLE/BUNDLE), `shipping_included`(YES/NO/UNKNOWN), `verification_method`, `quote_valid_until`, `deduction_terms`, `memo`
- `price_type`: `ASKING`, `SOLD_LISTING`, `BUYBACK_QUOTE`, `USER_REPORTED`. **`VERIFIED_SALE`은 가져올 수 없습니다.**
- `condition`: `UNOPENED`, `LIKE_NEW`, `GOOD`, `FAIR`, `POOR`, `BROKEN`
- 날짜는 `YYYY-MM-DD`, 금액은 숫자만(원화는 정수).
- 오류가 있는 행은 건너뛰고 행 번호와 이유를 화면에 보여 줍니다. 올바른 행만 저장됩니다.
- 내보낸 파일에는 `input_route`, `is_demo`, `item_name` 열이 더 붙습니다(다시 가져올 때는 무시).
- 내보낼 때 `=`, `+`, `-`, `@`, 탭, CR로 시작하는 글자 칸 앞에는 `'`를 붙여 스프레드시트가 수식으로 실행하지 않게 합니다. 금액 같은 숫자 칸은 숫자로 둡니다.

## 백업과 복구

개인 자료는 모두 `data/resale.db` 한 파일(과 실행 중 생기는 `-wal`, `-shm` 파일)에 있습니다. `data/`는 Git에 올라가지 않습니다.

**백업** — 앱 화면 맨 아래 "전체 자료 백업 파일(.db) 받기"를 누르면 `resale-backup-날짜.db`를 내려받습니다(<http://127.0.0.1:3000/api/backup>). 앱을 켠 채로 받아도 일관된 사본입니다. 실제 자료와 데모 자료가 모두 들어 있고, 데모는 DB 안에서 구분되어 있습니다. 터미널에서 직접 만들 수도 있습니다:

```bash
sqlite3 data/resale.db ".backup 'data/backup-2026-11-11.db'"
```

**백업 사본** — 설정 화면의 "지금 백업 사본 만들기"는 같은 사본을 내려받는 대신 이 컴퓨터의 `data/backups/resale/`에 `resale-날짜-시각.db`로 쌓아 둡니다. 버튼을 누를 때만 만들고 자동으로 지우지 않습니다. 휴지통을 비우거나 가격 자료를 여러 건 지우기 전에 만들어 두면 됩니다.

**읽을 수 있는 내보내기** — 화면 맨 아래 "읽을 수 있는 전체 내보내기(.json) 받기"는 지금 모드의 물건·가격 자료·비용 계산·받은 제안·올린 가격·판매 결과와 내 비용 묶음·판매글 템플릿을 JSON으로 내려받습니다(<http://127.0.0.1:3000/api/export/all>). 다른 도구로 열어 보거나 보관하는 용도이고 **복구용이 아닙니다**(다시 가져오는 기능 없음). 물건을 가로지르는 총액과 설정(가져오기 토큰 등)은 담지 않습니다.

**복구** — **앱을 끈 뒤** 실행합니다:

```bash
pnpm db:restore ~/Downloads/resale-backup-2026-11-11.db
```

- 이 앱의 DB가 맞는지(SQLite 형식, 필요한 테이블, 무결성 검사) 먼저 확인하고, 아니면 아무것도 바꾸지 않습니다.
- 바꾸기 전 현재 DB를 `data/resale.before-restore-<시각>.db`로 남깁니다.
- 앱이 켜져 있으면 열린 연결이 옛 파일을 계속 쓰므로 복구가 제대로 반영되지 않습니다.
- 백업 파일에는 휴지통에 있는 물건도 들어 있습니다.

물건과 가격 자료를 삭제하면 바로 지워지지 않고 **휴지통**(`/trash`)으로 가므로, 실수로 지운 것은 백업 없이도 되살릴 수 있습니다. 휴지통의 "완전히 지우기"와 "휴지통 비우기"는 되돌릴 수 없습니다.

가격 자료만 따로 보관하려면 실제 사용 모드에서 <http://127.0.0.1:3000/api/export/prices> 를 열어 CSV로 받을 수 있습니다(물건 정보·계산·판매 결과는 포함되지 않습니다). 물건 목록은 `/api/export/items`, 배분·판매 결과 표는 `/api/export/triage`·`/api/export/results`로 받습니다.
