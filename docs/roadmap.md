# 후속 항목

우선순위 순서가 아니라 묶음별 목록이다. 핵심 흐름을 써 본 뒤 필요한 것부터 고른다.

## 가격 자료

- **공식 가격 API 연동** — 접근 권한을 확보한 출처가 생기면 `src/lib/providers/price.ts`의 `PriceProvider`를 구현해 붙인다. 출처가 제공하는 가격의 의미(희망가/판매완료/체결가)를 문서로 확인한 뒤 유형을 정한다.
- **`VERIFIED_SALE` 활성화** — 실제 체결가 제공이 문서로 확인된 출처가 있을 때만. 검증 근거 저장은 이미 강제되어 있다.
- **같은 매물의 가격 변동 기록** — 지금은 매물당 한 건만 두고 수정한다. 확인일별 이력이 필요해지면 별도 테이블로 분리.
- **요약값 기준 조정** — 3건 기준이 실제 사용에 맞는지 판매 결과 기록이 쌓인 뒤 다시 본다.

## 상품 식별

- **게임기·전자기기 자동 식별** — 모델명 정규화 사전, 세대·용량·색상 구분.
- **구성품에 따른 비교** — 박스·충전기·컨트롤러 유무를 구조화해 "같은 구성끼리" 비교. 구성 차이를 금액으로 보정하는 것은 근거 자료가 쌓인 뒤에만 검토.
- **국내 서지정보 보강** — 국립중앙도서관 연동의 실제 호출 검증(키 발급 후), 판본 정보 품질 확인.
- **바코드 카메라 인식, 사진 첨부.**

## 해외·통화

- **해외 가격 비교** — eBay 등. 환율과 기준일을 명시적으로 입력받아 환산 근거를 남기고, 원화 자료와는 여전히 따로 보여 준다.

## 판매 과정

- **판매처별 비용 시나리오** — 지금은 업체/개인 두 가지. 판매처 여러 곳을 나란히 비교.
- **판매글 템플릿 여러 벌** — 판매처별 글자 수·양식.
- ~~물건 배분~~ — `/triage`로 구현. 다음 단계 후보: 판매처별 시나리오가 생기면 판매처 단위 배분.
- ~~판매 결과 돌아보기~~ — `/results`로 구현. 다음 단계: 카테고리·판매처별로 묶어 보기.
